# Why Humanoid? agent setup

Public access needs no account or key. The free catalogue is available in full. Deployments and Components expose only their public summaries and sources to visitors. An active data subscription and an API key provide the complete records. Catalogue entries report what their sources say. Check the original source, date, model and test conditions. Missing values are left blank or marked as unknown.

## MCP

Connect to https://whyhumanoid-premium.javier-198.workers.dev/mcp using Streamable HTTP. For public data, omit the Authorization header. Initialize the session and use `tools/list` to read the current tools and argument schemas. Then call `tools/call` with a tool name and its arguments.

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"search_catalogue","arguments":{"query":"","category":"humanoids","tags":"platform:bipedal,hq:united_states","page":1}}}
```

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"get_rows","arguments":{"table":"humanoids","query":"Atlas","limit":10,"offset":0}}}
```

## HTTP API

Base URL: https://whyhumanoid-premium.javier-198.workers.dev

```sh
curl -fsS 'https://whyhumanoid-premium.javier-198.workers.dev/v1/datasets'
curl -fsS 'https://whyhumanoid-premium.javier-198.workers.dev/v1/search?category=humanoids&tags=platform%3Abipedal%2Chq%3Aunited_states'
curl -fsS 'https://whyhumanoid-premium.javier-198.workers.dev/v1/datasets/humanoids?q=Atlas&limit=10'
curl -fsS 'https://whyhumanoid-premium.javier-198.workers.dev/v1/datasets/deployments/preview'
curl -fsS 'https://whyhumanoid-premium.javier-198.workers.dev/v1/verification'
```

Use comma-separated IDs from earlier search facets in tags. The hq: prefix filters company country, site: filters deployment country, and platform: filters robot mobility. Only records with the corresponding tags can match. Send free text as `q` over HTTP and `query` in MCP. Search returns paginated results and the available facets. Humanoid row responses include verification.by_row_id keyed by the unchanged row id. Read metrics.payload_sustained_bilateral_kg for sustained bilateral payload; Pending_Audit and not_disclosed are not zero. Do not parse the legacy Payload/carry (kg) string into this metric. Apply client-side thresholds only to this exact metric with its evidence tier, freshness and conditions; compare only matching reviewed comparison_group values. Peak, single-arm and unclassified payload remain separate. The server has no numeric payload filter.

## Attribute verification

The public `/v1/verification` endpoint describes Verification Standard v1.0. Add `?entity=<canonical-humanoid-slug>` for a robot's structured attributes and append-only history. Optional `valid_at=YYYY-MM-DD` and `known_at=YYYY-MM-DD` distinguish the specification period from the information recorded by that date. Unknown effective dates are not backdated. Each metric includes `verification_tier`, `verified_at`, `conditions` and `freshness`; the response adds `comparison_caveats`. The whole profile remains `Pending_Audit`. V1 records a manufacturer claim, V2 documents a scoped attribute, and V3/V4 require the independent evidence in [the standard](https://whyhumanoid.com/method/#verification-standard).

## CLI

Use Node.js 18 or later. [Read the source](https://whyhumanoid.com/agents/whyhumanoid.mjs) before running it.

```sh
curl -fsSLO 'https://whyhumanoid.com/agents/whyhumanoid.mjs'
node whyhumanoid.mjs categories
node whyhumanoid.mjs search '' --category humanoids --tags 'platform:bipedal,hq:united_states'
node whyhumanoid.mjs rows humanoids --query Atlas --limit 10
```

## Subscriber access

Create an API key in [Agent access](https://whyhumanoid.com/app/#keys). Send it as `Authorization: Bearer YOUR_API_KEY` to the API or MCP server, or set `WHYHUMANOID_API_KEY` for the CLI. Rates are 60 requests per minute and 5,000 per day per key. Follow `Retry-After` if you receive HTTP 429. The MCP tools are read-only.
